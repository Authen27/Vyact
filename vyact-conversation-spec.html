The conversation is one turn deep

Every message Vyact can send today is a terminal reply. It logs and confirms, or it refuses. It cannot ask a question, offer a choice, check a duplicate, accept a correction, or remember the previous message. That single limitation — not the copy — is what makes the conversation feel unresponsive, and it is what this spec exists to fix.

Three findings from this list

Four of thirteen are not Vyact copy. hello_world, 3p_direct_integration_test_template, feedback and recurring are Meta samples and test artifacts sitting in a production namespace. recurring is actively dangerous — it says a card payment is overdue, and its name invites confusion with the real recurring_auto_logged.

reengagement_nudge is a Marketing template. That is a different regulatory object: it needs marketing opt-in, honours a separate opt-out, and is suppressed for users who have opted out of promotions. It cannot be written in the same voice as the Utility set, and a user who mutes it must still receive bill reminders.

Nothing has ever been delivered. Zero messages, zero read rate across all thirteen. Every template here is unproven copy — there is no performance data to defend any of it, which makes this the cheapest moment to rewrite.

The core requirement

Seven turn types

“Intuitively responsive” is not a tone — it is a guarantee that every user message produces exactly one of these seven turns, and that the user always knows what to do next. Every message written from here on must declare which type it is and satisfy that type's rule.

01 · Acknowledge

Received, working on it. Only when the next turn will take more than a moment.

Never alone. Must be followed by a Result, Ask or Recover.

02 · Result

Something happened. Says what was recorded, where, and how to reverse it.

Always carries an undo path. One line.

03 · Ask

One thing is genuinely unclear. Offers two to four concrete choices, never open text.

Max one Ask per turn. Numbered replies on WhatsApp, chips in-app.

04 · Confirm

A draft is ready but a model read it, so a human approves before it becomes money.

Shows every field it inferred. Yes and No are equally easy.

05 · Refuse

We won't do this here. Names the reason and where it can be done.

Never a dead end. Never apologetic. Never blames the user.

06 · Recover

Something failed on our side.

Reassure about their data before explaining. Give one action.

07 · Nudge

Unprompted. Must be worth the interruption on its own.

Carries its own off switch. Frequency-capped. Never during quiet hours.

The contradiction to resolve

Ask “what's my balance?” on WhatsApp and Vyact replies “For your security, balances and reports live in the app 🔒”. Minutes later budget_threshold_alert and weekly_summary send spend figures to that same thread. Both behaviours are intentional; together they read as arbitrary.

Recommended resolution: the rule is not “no figures over chat” — it is “Vyact sends you your own figures on a schedule you chose; it does not answer queries in a channel it cannot authenticate.” That is defensible, and it makes the refusal copy honest instead of evasive.

Product question before any of this is submitted

Forecast is advice, not fact. A wrong bill reminder is an annoyance; a wrong “you can afford this” costs someone money. Decide whether Vyact gives opinions in a channel where it cannot show its working — and if yes, every forecast message must name the assumption it rests on, the way the in-app copy already does.

Constraints every message must satisfy

Requirements

CONV-01

Every inbound message gets a reply

Silence is the current failure mode for anything unparseable. No user message may end without a turn — even “I didn't understand that” is a turn, and it must offer an example that would have worked.

CONV-02

One question per turn, two to four options

Ask turns offer numbered choices, never open text. If more than one thing is unclear, ask about the most consequential and assume a correctable default for the rest. Users abandon interrogations.

CONV-03

Every answer merges without re-parsing

Replying “2” must apply that choice to the draft already held. The user never restates what they said. This is a design constraint on the options, not only on the engine: each option must be complete on its own.

CONV-04

Anything a model read gets confirmed; anything parsed by rule does not

Typed shorthand logs instantly, as it does today. A bank SMS or free text interpreted by the model produces a draft and waits. The user must be able to tell which happened from the message alone.

CONV-05

Every Result carries an undo

A logged transaction is money. The reply that announces it must also say how to take it back, in the same message, without opening the app.

CONV-06

A pending question expires, and says so

Questions are held for 30 minutes. After that a new message starts fresh rather than being read as an answer to something forgotten. The expiry must be visible in the copy — “still there?” beats silent abandonment.

CONV-07

Refusals route somewhere

Every “not here” names where it can be done, and offers the nearest thing that is possible in the channel. The current balance refusal and the “link it in Settings” reply both dead-end today — the second points at a flow that cannot complete, because the OTP template does not exist.

CONV-08

Nudges are opt-in, capped, and individually silenceable

A user who mutes re-engagement must still get bill reminders. Marketing and Utility are separate consents, and the copy must never bundle them. Cap: one proactive message per day, none during local night hours.

CONV-09

The same turn renders twice

One definition per turn, two renderings: numbered list on WhatsApp, tappable chips in-app. Copy is written once and must read naturally in both — which rules out “tap the button below” and any layout that assumes a screen.

CONV-10

Never state a figure the app did not calculate

Already enforced in code: a reply containing a number no calculation produced is discarded rather than shown. Copy must not fight this — no rounded approximations, no “roughly a third”, no derived percentages written into template text.

VOICE-01

Voice: calm, short, second person, no apology

Vyact states what happened and what is possible. It does not say sorry, does not exclaim, and does not congratulate people for logging an expense. Existing copy holds this well — “It'd be tight” rather than “You can't afford it” is the register to match.

VOICE-02

Money is never dramatised

No warning colours in words, no “alarming”, “blown”, “overspent”. Budget alerts report a fact and leave the judgement to the person whose money it is.
